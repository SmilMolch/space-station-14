# removeantag — административное снятие антагонистических ролей SS220


## Назначение

Команда `removeantag <логин> [traitor|thief|cult|initialinfected|headrev]` снимает **одну** конкретную роль у **подключённого** игрока, у которого есть работа на станции. При выполнении сохраняются `Mind`, тело, профессия, обучение и эффекты других ролей. Игрок получает приватное сообщение и окно «Потеря памяти» (культ использует штатное окно).

Поддерживаются предатель, вор, культист Йог-Сотот (кроме Ми-Го и превращающегося), нулевой пациент (до зомби) и глава революции. Другие роли, включая неисправного ИИ, **не** снимаются без отдельной реализации.

## Как проходит снятие

1. Определение подключённой сессии, тела и `Mind`; проверка базовой профессии и выбранного MindRole.
2. `CanRemove` соответствующей роли (включая запреты для Ми-Го, зомби и неподтверждённого происхождения бонуса).
3. Отзыв специальных эффектов и доступов роли. Для культа используется штатная очистка SS220.
4. Удаление только относящихся к этой роли целей и `MindRole`.
5. Отзыв записанных старых бонусных очков, пересчёт опыта **из действующих источников**, откат только непокрытых покупок навыков.
6. Отзыв исходной выданной экипировки, пересчёт фракций с учётом других ролей, обновление игровых счётчиков.
7. Запрет повторного получения этой же роли в текущем раунде, обновление окна персонажа и приватное уведомление.

**Важно:** проверка до исполнения снижает риск частичного изменения, но это не транзакция: игровые системы SS14 не поддерживают общий атомарный rollback. Если любой этап падает уже после очистки, логируйте это как ошибку сервера и не считайте снятие успешным. Для PR нужны интеграционные тесты.

### Учёт экипировки

Для стартовых предметов используются только UID сущностей, созданных синхронно внутри назначения конкретной роли: сервер подписан на `IEntityManager.EntityAdded`, а снимок назначения активен лишь между `BeginGrant` и `EndGrant`. Это устраняет двухкратный перебор всей карты. Отслеживание предметов позднего создания должно добавляться отдельно при их реальном создании. В частности, **содержимое выбранного позже набора вора не отслеживаем** согласно ТЗ.

Аплинк теперь возвращается из `UplinkSystem.AddUplink` через совместимую перегрузку с `out grantedStore` и `out grantedImplant`. Старый API для иных вызовов сохранён.

### Опыт и знания

`RoleExperienceAddComponent` содержит схему профессии. Для дополнительных знаний используются источники ролей; старый бонус `AntagFreeSublevelPointsAddComponent` отслеживается как дельта конкретного назначения. В нашем подтверждённом тесте предателя значения были 20 → 30 → 20; при затраченных очках журнал покупок вернулся к первоначальному состоянию. **Не обнуляйте опыт всего персонажа:** это уничтожит независимое обучение и другие источники.

## Подключение нового антагониста

1. Найдите все точки его назначения (включая поздний вход и обращения посреди раунда), перечень компонентов, действия, предметы, интерфейсы, фракции, цели и бонусы опыта.
2. Зарегистрируйте ID MindRole в `RemoveAntagRoles.cs` и объявите алиас команды **только после готовности полной очистки**.
3. Записывайте вновь выданные сущности в `AntagRemovalGrantComponent` **при выдаче**. Если используется новая механика, добавьте её в `BeginGrant`/`EndGrant` или в отдельную событийную точку назначения.
4. Дополните `CanRemove` проверками необратимых состояний. В `TryRevokeRoleEffects` отзывайте эффекты только данного антагониста; существующие эффекты других ролей не трогайте.
5. Добавьте знания через источники, а не разовыми изменениями `ConstantKnowledge`. При снятии удалите источник и сделайте единый пересчёт. Учитывайте разделяемые бонусы.
6. Обновите игровое правило (счётчики, лимиты), пользовательское название и строки локализации.
7. Подготовьте тесты: только одна роль, 2 роли сразу, уже потраченные очки, предмет на полу, отключение, смерть, отсутствие профессии и повторная выдача.

Для неисправного ИИ дополнительно потребуются сохранение и возврат **предшествующих** законов. Не включайте ИИ в список поддерживаемых ролей до появления полноценного обработчика.
