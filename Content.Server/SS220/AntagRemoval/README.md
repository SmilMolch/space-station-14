# Как добавить нового антагониста в `removeantag`

1. Найдите ID прототипа `MindRole` и все штатные пути его назначения через GameRule и административную команду. Проверьте, что назначение проходит через `AntagSelectionSystem.MakeAntag()` (для конверсий — добавьте отдельную точку фиксации).
2. Добавьте ID в `RemoveAntagRoles.cs`, аргумент в `RemoveAntagSystem.Supported`, подсказку в `RemoveAntagCommand.GetCompletion()` и название роли в `Resources/Locale/ru-RU/ss220/removeantag.ftl`. Разные способы назначения одной `MindRole` не требуют разных команд.
3. В `Handlers` создайте новый `EntitySystem`, реализующий `IAntagRemovalHandler`. Метод `CanRemove` проверяет возможность снятия **до изменения состояния**, `TryRemove` удаляет только специфические последствия роли. `RemovesMindRole = true` используйте, если уже существующий обработчик деконверсии сам снимает `MindRole`.
4. Добавьте систему в `RemoveAntagSystem.GetHandler`. Универсальные действия (удаление `MindRole`, целей, записанных предметов, перерасчёт опыта, фракций, уведомление, аудит и освобождение слота) не дублируйте внутри обработчика.
5. Если роль выдаёт предметы, учитывайте **конкретные UID** через `BeginGrant` / `EndGrant` или узкую интеграцию назначения. Передача другому игроку не должна мешать отзыву предмета. Не удаляйте чужие предметы только по совпадению прототипа.
6. Проверьте регистрацию опыта и знаний в `AntagExperienceSourcesComponent`; для особых способов выдачи создайте отдельную интеграцию. Отзыв должен сохранять обычные знания, профессию и бонусы других активных ролей.
7. Проверьте назначение в начале раунда, через штатную админскую команду и midround (если доступно), снятие, повторное назначение, освобождение исходного слота, переданные предметы и повторный перерасчёт опыта. Соберите сервер и клиент и проверьте окно `RoleRemovalNotice`.

Не добавляйте роль в `Supported`, пока неизвестно, как безопасно отменять её эффекты. Прямое редактирование `MindRole` через VV не поддерживается отдельно.
